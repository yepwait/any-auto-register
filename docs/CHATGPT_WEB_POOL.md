# ChatGPT Web 池巡检（独立于 Codex／RT 巡检）

本功能通过当前项目统一注册和保存账号，再同步到 chatgpt2api 的 Web 图片号池。自动维护支持实时通知与定时兜底；Web 注册本身禁止手机接码、Codex RT 授权和全局外传。账号之后仍可由用户选择进入接码补库，注册来源不等于永久能力限制。

## 它做什么

1. 读取远端号池：`GET {root}/api/accounts`，`Authorization: Bearer <管理员密钥>`。
   - `legacy`：只统计 `status == "正常"`，图片额度为 `Σ max(0, quota)`，可用账号为正常且 `quota > 0`。
   - `yukkcat_v3`（已按 3.2.9 源码核对）：逐页读取 `items/total/page/page_size`，使用 `backend_status/available/quota_remaining`，不要求远端回显 Token；缺页、重复 ID 或列表变化会中止本轮。
   - v3 的 `quota_unknown/quota_unlimited` 独立显示；数值额度目标遇到无法确定的额度就暂停注册，可用账号模式仍按远端 `available` 统计。
   - `auto` 默认按返回结构识别协议。认证或网络失败不会假装空池，也不会绕过错误回落到另一协议。
   - **这是 ChatGPT Web 图片生成额度，不是 Codex 文本额度，也不是实时上游余额**（远端读的是自己缓存的记录）。
2. 低于目标时补号：
   - 先补传本地“本用途待上传”的账号（避免重复注册）。
   - 再按需用本项目**邮箱注册**（`email` + `access_token_only`），**不接手机短信、不补 RT、不做 Codex OAuth、不走 CPA／Sub2API**。
   - 上传 `POST {root}/api/accounts`，只发送 `{accounts:[{access_token, email}]}`，不发送密码、RT、Cookie 或邮箱凭据。
   - legacy 按返回 Token/稳定身份核验；v3 保存 `updated_ids` 对应的稳定远端 ID，按脱敏投影的 `available` 和同步错误核验。HTTP 200 不等于账号可用。
   - v3 的凭证更新使用 `/api/accounts/update`（按保存的 ID），再 `/api/accounts/sync` 并等待 `/api/accounts/operations/{progress_id}` 的布尔 `done` 与结果核对，不能用新 AT 再创建一份重复账号。
   - 补 RT 或探测后 AT 改变会标记 `needs_resync`；即使总额度已达标，也可补同步既有账号，不新增注册。旧同步记录没有 v3 远端 ID 时明确要求核对映射，不按相同邮箱盲目更新。
   - v3 导入保留 `sync_after_import=true` 的账号状态/额度同步语义；这会请求远端上游账户接口，并可能按远端配置移除失效账号，但不会进行注册、手机接码或出图。
3. 次数策略：每轮最多尝试、每日注册上限（UTC）、连续失败停止阈值均支持 **0＝不限**。正数保持原有上限语义；三个值都是0时可能持续尝试并产生邮箱费用，仍在目标达标、手动停止、配置改变或远端额度/请求异常时停止。开发记录及发布状态见 [两个零值不限说明](WEB_POOL_UNLIMITED.md)。
4. 结果落库：账号 `extra.account_purpose = "chatgpt_web_pool"`，并记录 `sync_statuses.chatgpt2api` 的脱敏结果。

## 关键安全边界

- 远端额度/结构读不到或不可解析时**停止补号**，绝不把“未知”当作 0 去盲目注册。
- 远端鉴权失败（401/403）、非 2xx、返回登录页 HTML、业务错误都视为失败并停止本轮。
- 不跟随重定向（避免带着管理员密钥跳转），不读取进程代理/netrc。
- 请求失败/超时时，账号保留本地，下一轮先 `GET` 复核是否其实已入池，避免重复注册。
- 日志和前端只展示脱敏统计，不打印 token、密钥或整池 `items`。

## 与其他流程的关系

- **「接码自动补库」可以把这些账号当作普通可处理账号**：Web 池账号（有 access_token、还没 RT）会进入接码补库的“已注册未接码／可补 RT”候选，补 RT 成功并拿到 RT 后会计入接码库存。手工/批量“补 RT”也会选到它们（同一套 RT 链路）。
- Web 池账号仍然**不进入「Codex／RT 巡检中心」**，也**不会自动外传到 CPA／Sub2API／CodexProxy**（注册后自动同步被跳过，账号页的上传类动作对这些账号返回拒绝），避免凭证被悄悄送到别处。如需外传请用普通账号流程。
- 账号管理页显示“Web 注册来源”；SMS/RT/AT/套餐状态按实际结果显示，真实接码记录优先，Web 来源不再覆盖“已接码”或 RT 探测状态。同步凭证变更时先显示“凭证更新待同步”，不会沿用旧的可用标签。

## 如何配置

进入侧边栏“Web 池巡检”页面：

- **远端 Root URL**：`chatgpt2api` 服务根地址（如 `https://your-host` 或带反代前缀），不要填 `/api/accounts` 或 `/health`。
- **管理员 Bearer 密钥**：远端管理员密钥（不是普通用户 Key），保存后不回显，留空表示保留原值；**更换地址时必须重新输入密钥**。
- **目标口径**：剩余图片额度 或 可用账号数。
- **目标值 / 间隔 / 每轮上限 / 每日上限 / 连续失败上限 / 请求超时**。
- **每日注册上限（UTC）**：`0` 表示每日不限，`1～1000` 表示当天最多发起的注册尝试数（失败也计数）。不限时仍记录当天用量，状态接口用 `daily_registration_unlimited=true`、`daily_registrations_remaining=null` 表示不限，不使用 `0` 冒充剩余次数。修改此值不会清零当天用量；启用补号仍需确认可能产生的邮箱费用。
- **每轮最多尝试次数**：`0` 表示本轮不限，正整数1～100为上限；待上传账号处理也计入本轮尝试。0不表示执行0次，也不更改每日预算。
- **连续失败停止本轮**：`0` 表示不按连续失败次数停止，正整数1～10为停止阈值。远端鉴权失败、结构错误或上传结果不确定仍会停止，不因0盲目重复注册。
- 无限次数运行会限速避免空转：配置间隔为0时成功轮次至少间隔0.25秒、失败轮次至少1秒，并在等待期间检查停止与配置变更；这不是隐藏的次数限制。
- 右侧“已保存”策略与左侧“未保存编辑”分开显示；历史任务始终使用创建时的配置，日志不会追随后来修改。额度未知用独立 `meta.outcome=quota_unknown` 表示等待确认，任务已结束但不记为注册失败。

操作：

- “检查已保存配置”：只读远端，不保存表单、不启动注册。
- “按已保存配置执行一次”：需确认邮箱费用后创建任务。
- 启用定时巡检：保存并确认邮箱费用；关闭→开启时唤醒调度器立即执行一次。

> 邮箱注册可能产生邮箱费用（取决于全局邮箱供应商）；本功能只承诺不使用手机接码。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/chatgpt-web-pool/config` | 读取配置（密钥不回显） |
| PUT | `/api/chatgpt-web-pool/config` | 保存配置；启用需 `confirm_registration` |
| GET | `/api/chatgpt-web-pool/status` | 本地状态、最近快照、待上传数、每日用量、任务历史（不访问远端） |
| POST | `/api/chatgpt-web-pool/check` | 用已保存配置只读远端额度 |
| POST | `/api/chatgpt-web-pool/run` | 需 `confirm_registration`，创建补号任务 |
| POST | `/api/chatgpt-web-pool/trigger` | 必须配置并匹配触发密钥；先保存合并待办，再返回 202，不直接表示注册已执行 |

## 实时通知的可靠性与阈值

- `chatgpt_web_pool_trigger_secret` 必须非空，否则 `/trigger` 返回 503 并关闭入口。正常请求使用 `X-Replenish-Secret`，旧 body.secret 仍兼容；相邻接口仍走面板 JWT。
- 最大请求体 4096 字节（也检查 chunked 实收字节）。每个进程固定限流桶，超过返回 429 + `Retry-After: 5`；不会为每个 IP 或事件创建无限队列。
- 可带 `event_id`（不超过128字符）和 Unix秒 `sent_at`（允许10分钟时间差）。只保存最近128个事件摘要用于10分钟内去重，不存密钥或通知里的地址/额度；发送方额度仅是提示，不能覆盖本地配置。
- 确认收到前，先在 SQLite configs 保存一份合并待办；一个固定后台线程被唤醒后检查。忙时最多每5秒检查空闲并保留待办，不为每次通知创建注册线程。
- 单轮达到已配置的正数尝试上限但仍不足，会保留补足待办；远端故障最多3轮自动重试，随后进入5分钟熔断窗口，不因同轮新通知无限绕过。此处是事件故障退避，与用户配置的账号连续失败阈值不是同一项。日上限耗尽等待下一个 UTC 日；每轮、连续失败和每日次数只有配置正数时才限制。额度未知等待新的远端数据或策略确认，不自动反复创建失败任务。
- 改目的地址、密钥或策略会停止旧代任务、使旧待办失效；手动停止不会立即自动恢复。服务重启会重新核对额度，不直接盲目重复注册。
- `refill_below=0` 沿用 `target_value`，保持旧配置行为。需要双阈值时，开始阈值不能大于补足目标，例如低于2000开始、补到2300停止。已开始补足的实时任务跨批次保留这个阶段。
- `/status.realtime` 返回已收到、待办、等待空闲、处理中、冷却、错误等状态；HTTP 202 只代表通知已处理/排队，不等于注册/上传成功。

发送方建议只报告额度变化；若仍有本地阈值，应与注册机策略协调。此前直接修改 chatgpt2api Volume 的发送补丁不是本仓库可重复构建的一部分；此次接收端优化不会自动修复发送端丢事件、配置热加载或升级覆盖问题。上线前仍需确认发送端确实发送，并在无付费副作用的测试环境验证两端闭环，不能把单次接口200当完整验证。
