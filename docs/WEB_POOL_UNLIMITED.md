# Web 池两个次数阈值支持 0＝不限

日期：2026-11-12。

**状态：已按用户确认部署至 https://sdk.yepoodai.cn，版本 `web-unlimited-20261112T085603Z`；未提交或推送。** 用户选择“部署功能，保留现有配置”，所以线上仍为每轮5次、连续失败3次、每日0不限；本次没有将任何参数自动改成0，也没有手动触发真实注册/接码/支付。原有自动任务已恢复。

## 明确语义

| 参数 | 0 | 正数 | 原默认 |
| --- | --- | --- | --- |
| 每轮最多尝试次数 `max_attempts_per_run` | 本轮不限制次数，不是执行0次 | 1～100，最多相应次数 | 5，不改变 |
| 连续失败停止本轮 `max_consecutive_failures` | 不按连续失败次数停止 | 1～10，达到连续失败次数就停止本轮 | 3，不改变 |
| 每日注册上限 `daily_registration_limit` | 当日不限制次数（已有行为） | 1～1000，失败也计数 | 20，不改变 |

本轮只增加能力，**不替用户把任何现有值改成0**。表单填写后仍需保存和费用确认。每轮尝试包括本用途待同步账号上传与新注册处理；每日用量只在实际发起新注册前预留。

## 不限仍会停止的情形

- 远端已达到目标，或尚未低于开始阈值，不再新注册。
- 手动停止、关闭自动维护或配置/目标改变。
- 每日上限为正数且已经用尽。
- 管理员鉴权失败、网络/结构错误、账号上传结果不确定等安全中断；这些不是连续账号失败次数上限。
- 数值图片额度模式遇到未知/无限额度，无法比较目标，不按0盲目花费注册。

如果三个次数配置全为0、远端持续不足、邮箱注册持续失败，任务可能一直尝试并持续产生邮箱费用。确认弹窗明确提示该风险，不能把“无限制”说成“免费”或保证自动成功。

## 长运行资源与节奏

- 仅在正数时比较本轮/连续失败上限，没有用一个很大的数字冒充不限。
- 无限本轮且配置间隔为0时，成功轮次至少间隔0.25秒、失败轮次至少1秒；非零配置间隔取两者较大值。等待中每0.25秒检查停止/配置，避免无网络立即失败时忙等。
- 错误累计计数持续增长，错误样本仅保留最近100条；运行中/持久化摘要的 `error_count` 仍是真实次数，不被100条样本截断。
- 父任务仅保存最近100个子任务ID的便利索引；完整子任务由原有 `parent_task_id` 在数据库中关联，日志仍按原追加式存储。
- 每轮重新筛选待同步账号，已确认账号ID不持续累积在运行内存中。
