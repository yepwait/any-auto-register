## 已完成

### 1. 实时通知持久待办

- POST `/api/chatgpt-web-pool/trigger` 必须先完成触发密钥校验，再将一份合并待办保存到 SQLite configs。
- 返回 HTTP 202 表示请求已响应；只有 `accepted=true` 才表示待办被接收，不等于账号已注册或可用。
- 固定后台 worker 处理待办；忙时保留待办，空闲后复核，不能用 HTTP 200/202 冒充“本次补号已成功”。
- 一个号池至多一份待办及一个活动联动任务，重复事件合并；最近事件摘要有条数与时间上限。
- 后台 worker 未启动或服务关闭时，待办不凭空产生付费行为。维护预检可使用 `APP_ENABLE_SCHEDULER=0` 同时关闭调度与实时处理 worker。
- 临时失败有限重试、退避与熔断；运行期间的新通知不能绕过失败上限。
- 日上限耗尽等待次日 UTC。后续已按用户要求实现并部署每轮/连续失败0＝不限；正数才限制次数，目标、人工停止和远端异常检查仍保留，具体开发与发布状态见 [无限次数说明](WEB_POOL_UNLIMITED.md)。
- 配置变化、密钥撤销或轮换使旧待办失效，运行任务在下一检查点停止；手动停止不立即自动复活。

### 2. 鉴权和请求边界

- 未配置触发密钥返回 503，不能匿名执行；错误密钥返回 401。
- 只有精确 POST trigger 路径使用独立触发鉴权，相邻 API 保留面板 JWT 保护。
- 密钥采用恒定时间比较；请求体实际字节不超过 4096，覆盖无 Content-Length/chunked 场景。
- 进程级固定大小限流桶；事件 ID 有界去重；时间戳过期拒绝。
- 通知中的额度、阈值和 URL 都不能覆盖注册机保存的策略或上传目标。

### 3. chatgpt2api 接口兼容

- 默认 `protocol=auto`，也可明确选择 `legacy` 或 `yukkcat_v3`。
- v3 合约依据当时实际运行的 yukkcat 3.2.9 源码只读核对；不复用旧版 Token 回显假设。
- 分页必须完整、一致且 ID 不重复；结构异常、鉴权失败、网络失败均不解释为 0 额度。
- v3 可用账号按 `available` 统计；未知/无限额度单独呈现，不编造数值。数值额度模式无法比较未知值时停止注册，可用账号数模式仍可使用。
- 单账号导入保存返回的稳定 `remote_id`；同步更新按该 ID 调用 update → sync → operations → detail，严格核验完成布尔值、错误和目标 ID。
- 既有同步记录没有 v3 远端 ID 时明确提示核对映射，不依赖相同邮箱盲目修改或重复创建。
- 只发送 Web AT/email，不发送密码、邮箱 RT、Cookie 或全局配置。导入同步保留原有远端状态/额度刷新语义，可能按远端策略移除失效账号。
- 同步轮询有超时及停止检查；中断/失败保持本地待复核，不误标成功。

### 4. 账号状态与凭证同步

- 来源标签为“Web 注册来源”，不再断言它永久免接码或无 RT。
- 页面真实接码记录优先，RT/AT/Codex 探测分别表达其含义；无探测时显示“有 RT/无 RT · 未检测”。
- 补 RT 或探测后 AT 变化标记 `needs_resync`，不能继续显示旧 ready 结果。
- 用单向凭证指纹确认同步的是哪个版本；上传过程中本地 AT 再变化时仍保留待同步。
- 总额度已达标时仍允许更新既有账号凭证，但不为此新注册账号。

### 5. 支付资源边界

- 支付批任务在统一入队锁中检查维护状态与任务容量；UUID 任务 ID，输入账号按顺序去重。
- 初始持久化/调度失败标记失败并保留可恢复记录，不留下无人执行的 pending。
- 单账号提链/支付在短数据库 Session 里读取快照后释放连接，再进入全局账号资源槽执行网络操作。
- 没有运行任何真实支付或提链请求，测试全部使用 mock。

## 上线前仍需注意

1. 这次是当前注册机接收端和协议客户端的可靠性优化，**没有改造或重新部署外部 chatgpt2api 的发送补丁**。发送端的线程/重试/配置重载及升级覆盖仍须单独治理，定时检查仅作兜底。
2. 老发送方不带 event_id/sent_at 的通知保持兼容；它可以忽略 202 响应体，但不能将 `triggered=false` 理解为永久丢弃，应该查看 accepted/queued。
3. 此前发送阈值和补足目标分开配置，需核对一致性。本轮未替用户更改数值；开始阈值必须小于等于目标，默认 0 沿用目标保持兼容。
4. 一个 Python 进程内共享锁/worker 的任务模型不支持简单叠加多个 uvicorn worker。数据库持久待办保证重启后的复核，不是多实例分布式租约。
5. 网络调用中的阻塞请求只能在超时或检查点后停止，不能承诺零延迟取消；强杀期间尚未确认的上传保留待复核。
6. 新代码已通过白名单发布包部署，必要的新模块和静态资源已核验；仍未推送 GitHub。后续发布仍须核对活跃任务、数据/密钥挂载及回滚版本，不能仅复制少数修改文件漏掉新模块。
